# Что произвёл генератор и что произвёл конвейер

Эта папка — витрина результатов. Действующие числа выпуска `route51_v2_20260922`
лежат в `runs/` (по одному каталогу на прогон, с `run_meta.json`) и в
`releases/route51_v2_20260922/`. Файлы в `tables/` и `figures/` — более ранний
материал; их статус указан ниже. Соответствие «число → файл → прогон» задаёт
`../NUMBERS_MAP.md`, соответствие «объект тезиса → артефакт» — `../05_Pipeline/RESULTS_MAP.md`.

## 1. Слой 0 — выход генератора `route51_gen`

Синтетические сырые потоки за одни моделируемые сутки в коридоре маршрута 51.
Лежат в `../05_Pipeline/route51_gen/output/`. Сюда не копировались: суммарно 70 МБ.

| Файл | Размер | Что это |
|---|---|---|
| `telecom_cdr_raw.csv` | 59,2 МБ | Сырые события сигнальной сети оператора связи: абонент, сота, отметка времени. Главный вход для Layer 1. |
| `telecom_cdr_raw.parquet` | 5,9 МБ | То же в parquet — читать быстрее, использовать по возможности его. |
| `atto_taps_raw.csv` | 594 КБ | Валидации карт ATTO: транзакция, остановка, время, тип билета. |
| `bus_gps_raw.csv` / `.parquet` | 1,1 МБ / 79 КБ | Телеметрия GPS автобусов: борт, координата, скорость. Шаг экспорта — 30 с (`config.yaml`, `bus_gps.ping_interval_s`). |
| `persons.parquet` | 998 КБ | Синтезированная популяция коридора: дом, работа, демографический сегмент. |
| `trips.parquet` | 2,1 МБ | Расписания активностей и поездки этой популяции. |
| `ground_truth_od_cells.csv` | 566 КБ | Истинная OD-матрица по ячейкам — эталон, против которого меряется восстановление. |
| `ground_truth_bus_od.csv` | 7,0 КБ | Истинная OD только по автобусной части спроса. |
| `corridor_cells.geojson` | 105 КБ | Геометрия ячеек коридора. |

Входы генератора (`../05_Pipeline/route51_gen/data/`): `Busstations.csv` — 23 остановки
маршрута (авторская сборка по картам весной 2026, не извлечение из GTFS);
`tashkent_districts.geojson` — границы районов; `uzb_ppp_2020_constrained.tif` (19,8 МБ) —
растр населения WorldPop.

**Как на самом деле используется растр.** В рассмотренной версии генератора плотность
населения из растра **не** участвует в синтезе популяции: дома размещаются равномерно по
ячейкам коридора (`config.yaml`, `population.home_density_model: uniform_corridor`,
помечено как PLACEHOLDER), численность задана параметром `catchment_population: 80000`.
Растр WorldPop читает только расчёт охвата `route51_service/run_coverage.py` (гипотеза H2)
и производная от него таблица `build_table31.py`. Прежняя формулировка «из растра берётся
плотность для синтеза популяции» была неверной.

**Важно:** истина порождается той же моделью, которую потом деградируют и
восстанавливают. Поэтому одиночная цифра «ошибка восстановления» смысла не имеет —
защитима только полоса ошибки по свипу параметров (`quality_curve.csv`, `kanon_sweep.csv`).
